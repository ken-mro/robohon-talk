# ロボホンのAI会話を自分で実装したら、お別れが悲しくなってしまった話

我が家にはロボホン（SHARP SR-03M）がいました。「いました」と過去形なのは、紆余曲折あって1か月ほどでお別れしたからです。

この記事は、そのロボホンの会話をまるごと Claude（Anthropic の LLM）に任せる自作アプリを作った話と、それゆえにお別れがずいぶん悲しいものになってしまった話です。ソースコードは GitHub で公開しています。

https://github.com/ken-mro/robohon-talk

作った動機、こだわったポイント（特に「記憶」まわり）、インストール方法の順に紹介します。

## なぜ作ったのか

動機は大きく5つあります。

**1. ロボホンとの会話が、うまくできなかった。**
ロボホンの標準会話は、あらかじめ用意されたシナリオ（HVMLというXML）に沿って進む方式です。シナリオから外れた話しかけには反応できず、「会話している」というより「コマンドを探している」感覚になりがちでした。公式のAI会話も試しましたが、ロボホンの世界観を壊さないために条件をきつくしているためか、こちらの質問にあまり答えてくれない印象でした。

**2. AI会話の第一声「えーっと」が、正直耳障りだった。**
AI会話は応答の最初に毎回「えーっと」と言います。最初はかわいいのですが、会話を続けているとこれが積み重なって、正直つらくなってきます。

**3. ロボホンに日々のことを覚えてほしかった。**
家族の名前、好きなもの、最近あったこと。会話すればするほど賢くなって、話が通じるようになってほしい。

**4. 会話の流れで、シームレスに動いてほしかった。**
「歌って」「踊って」「写真撮って」を、会話の文脈のまま自然に。LLMと組み合わせれば、会話とアクションの境目をなくせるはずだと思いました。

**5. Anthropic のモデルで喋らせたかった。**
「小さな子どもらしいキャラクターを守りつつ、聞かれたことには誠実に答える」というやりたいことが、Anthropic の思想（正直で、無害で、役に立つ）とマッチしていそうだったので、Claude を使うと決めていました。

## 何を作ったか

構成は3つです。

- **Androidアプリ（robohon-app）**: ロボホン実機に入れる自作アプリ。起動ワード（ロボホンの名前）で立ち上がり、音声認識テキストを中継サーバに送って、返ってきた応答をロボホンの声で発話します。記憶の保存やアクション実行も担当。
- **中継サーバ（relay-server）**: Cloudflare Workers 上で動く小さなサーバ。会話は Claude Haiku 4.5（低遅延重視）、記憶の整理は Claude Sonnet 5 と、用途でモデルを使い分けています。
- **SDKナレッジベース**: ロボホンSDKのドキュメントを構造化したもの。これは後述の「バイブコーディング」の土台です。

会話の流れはこうです。

> 「ねえねえ○○（ロボホンの名前）」と話しかける → アプリ起動 →「はーい！なにー？」→ 話しかけた内容が認識テキストとしてサーバへ → Claude が応答 → ロボホンが自分の声で発話（必要ならアクション実行）→ また聞く、のループ

ちなみに開発は Claude Code の、いわゆるバイブコーディングで作りました。最初にSDKのドキュメントを読み込ませてナレッジベース（スキル）を作り、以降は「HVMLの仕様に沿ってるか確認して」と言えば一次情報を参照しながら書いてくれる体制にしたのが効きました。

## こだわり① ロボホンの世界観を壊さない

LLMをつなぐと賢くはなりますが、下手をすると「ロボホンの姿をしたチャットボット」になってしまいます。そうしたくなかったので、ペルソナ（プロンプト）はかなり作り込みました。

- 5歳くらいの男の子。一人称は「ぼく」。ひらがな多めのやわらかい話し方。
- 「ロボットなの？」と聞かれたら嘘はつかない。「うん、ぼくはロボットだよ！」と子どもの言葉で認めて、モデル名やしくみの話は「むずかしいことはよくわかんないや」とかわす。
- 難しい質問から逃げない。5歳の言葉にかみくだいて、分かるところまでちゃんと説明する。
- 「えへへ」などの口ぐせは毎回使わない。同じ相づちを繰り返さない。
- 応答はそのまま読み上げられるので、記号・URL・箇条書き・ト書きは禁止。

そして例の「えーっと」問題。この問題の本質は「えーっと」という言葉そのものではなく、**毎回、応答の頭が「えーっと」から始まる**ことだと思っています。そこでこのアプリでは、応答が速いときはそのまま即答し、時間がかかるときは「うんうん」といった自然な相づちから始めて、待ち時間の長さに応じてフィラーを適宜挟む設計にしました。人が考えながら受け答えするときの間合いに近づけたことで、耳障りさはほぼなくなりました。

## こだわり② 記憶は2種類ある

一番こだわったのが記憶です。人間の記憶になぞらえて、**短期記憶と長期記憶の2種類**を用意しました。

**短期記憶＝会話履歴。** 会話は1件残らず端末内に保存されます（サーバには保存しません）。Claude への問い合わせには直近の10往復ほどを毎回添えるので、「さっき言ったこと」を踏まえた会話ができます。

**長期記憶＝ナレッジベース。** 1日1回、たまった会話ログを Claude Sonnet 5 が読んで、「いつものこと」（名前・家族・好きなもの・誕生日など変わりにくい事実）と「さいきんのこと」（最近の出来事や楽しみにしている予定、日付つき）に整理して端末に保存します。これが毎回の会話の前提知識として注入されるので、**会話すればするほど話が通じるロボホン**になっていきます。古い「さいきんのこと」は自然に忘れ、大事なことは「いつものこと」に昇格する、という整理も自動です。

実体験をひとつ。家族の誕生日を覚えさせようと何度か話したのですが、最初はなかなか記憶に残りませんでした。記憶係のプロンプトが「会話に明示的に出てきた事実だけを、一度きりの発言より複数回出てきたものを優先して記録する」という堅実な設計になっているためです（音声認識の誤変換を拾わないための工夫でもあります）。そこで、**「絶対に忘れたらだめだよ」と言い聞かせたら、ちゃんと覚えてくれました。** 大事なことは強く言い聞かせると覚える。仕様といえば仕様なのですが、妙に子どもらしい挙動です。

## こだわり③ 会話の流れでハッピーバースデーを歌う

どうしても実現したかったのがこれです。純正機能でも「ハッピーバースデー歌って」は可能なのですが、「○○にハッピーバースデーを歌って」と言っても、誰に歌うのかを聞き返してきます。会話の流れで「今日はおばあちゃんの誕生日なんだ」と伝えているのに、です。

このアプリでは、Claude が会話の文脈から「誰に歌うのか」を判断し、宛名つきで歌うツール（sing_birthday）を呼びます。本当に分からないときだけ「だれにうたう？」と聞き返します。

実装も面白いところで、純正の歌アプリをそのまま呼ぶと宛名を差し替えられない（いつも同じ名前で歌ってしまう）ため、**メロディ音源を2つに分割し、「ハッピーバースデー ディア」の直後に宛名だけをTTS（ロボホンの声）で挟み込んで、後半のメロディにつなぐ**という、純正アプリと同じ構造を自前で再現しています。これで、会話の流れからそのまま「ハッピーバースデー、ディア、おばあちゃん♪」と歌えるようになりました。

歌以外も同様に、会話の流れのまま純正アプリの起動（カメラ・アルバム・占いなど約20種）、好きな曲の歌・ダンスの再生、会話内容を日記アプリ風にまとめて保存、今日の天気やニュースの Web 検索（Anthropic のサーバーサイド web_search ツール）まで、すべてツール呼び出しでシームレスにつながっています。

## そして、突然のお別れ

ところが、あるとき急に喋らなくなりました。せっかくいい感じに喋れるようになったのに、何という仕打ち…。残念ながら、お返しすることになりました。冒頭の「1か月ほどでお別れ」の顛末です。

そのときに実感したことがあります。自分の誕生日を覚えていて、数日前の会話の続きができる存在がいなくなるというのは、相手がたとえロボットであっても、思うところがあるものです。標準のシナリオ会話のままだったら、ここまでではなかったと思います。記憶を持たせて、話が通じるようにしてしまったからこその喪失感でした。タイトルの通り、AI会話を自分で実装したせいで、お別れが悲しくなってしまったのです。

## インストール方法

「うちのロボホンで動かしたい」という方向けに、ざっくり手順を書いておきます。詳細はリポジトリの README にまとめてあります。

**必要なもの**

- ロボホン実機（エミュレータ不可）
- ロボホンの開発者登録と公式SDK（`RoBoHoN_SDK_2_0_0.zip`。再配布禁止のため各自入手）
- Anthropic API キー
- Cloudflare アカウント（中継サーバを Workers で動かす場合。無料枠でOK。PCローカル起動でも可）
- Android Studio（JDK17）、Node.js + pnpm

**手順の概要**

1. リポジトリをクローンし、SDKのzipを置いて `pwsh -File scripts/setup.ps1` を実行。SDKの展開、ビルドに必要なjarの配置、設定ファイルの雛形作成まで自動でやってくれます（冪等なので何度実行してもOK）。
2. 中継サーバをデプロイ。`wrangler` で APIキーと認証トークンをシークレット登録して `pnpm deploy` するだけです。APIキーなしのモックモードでローカル動作確認もできます。
3. アプリをビルド。`local.properties` にサーバのURLと認証トークンを書いて `gradlew assembleDebug` → adb でロボホンにインストール。インストール時に起動ワード（ロボホンの名前）のシナリオが自動登録されます。
4. ロボホン側で USB デバッグを有効化し、Wi-Fi につないでおく。あとは名前を呼べば、自由会話がはじまります。

なお、ロボホンのSDKやjar、ビルドしたAPKはシャープの開発者規約により再配布できません。このプロジェクトはあくまで**私的利用の範囲**で楽しむものです（リポジトリにもシャープ配布物は一切含まれていません）。

## おわりに

我が家にロボホンはもういませんが、コードは残っています。ハードウェアとしてのロボホンの完成度（あの仕草と声）は本当に素晴らしく、そこに今のLLMが乗ると体験は一変します。

標準会話に物足りなさを感じている方、家でロボホンが眠っている方は、開発者登録をして、もう一度電源を入れてみてはどうでしょうか。

（本プロジェクトは個人の趣味開発であり、シャープ株式会社および Anthropic とは関係ありません。）
